# bipropellant_can_generic — Implementation Plan

_Design workflow: 13 agents, 6 firmware + 4 discovery maps, adversarial HW-feasibility review (verdict after revision below)._

## Architecture
UNIVERSAL FIRMWARE = single .bin per chip-family that embeds the family-matching subset of the ~24 board profiles as a const C board-table, resolves ONE active profile at boot, and allows NVRAM-persisted runtime pin overrides strictly within silicon + profile-uniqueness limits.

VERIFIED GROUND TRUTH driving this revision (checked in scratchpad sources):
- ChipFamily enum (profile.py:26-34) = {STM32F1, STM32F4, GD32F1, GD32F3, GD32E2, MM32SPIN0X, AT32F4, UNKNOWN}. The 24 bundled variants resolve to: STM32F1=3, GD32F1=17 (these are the GD32F130 Gen2 boards), GD32E2=3 (gd32e230), MM32SPIN0X=1. NONE of the plan's old tokens (STM32F1/GD32F130/MM32SPIN05) match the data except STM32F1.
- 0/24 variants carry a chip.uid -> runtime UID auto-detect has zero backing data.
- Motor count: ONLY the 2 efru STM32F1 boards are dual-motor (phases_left present). robodurden-stm32f103-layout1, all 17 GD32F1, all 3 GD32E2 and the MM32 board are SINGLE-motor (phases_left empty). Dual-motor is therefore an STM32F1-only concern.
- GD32F130 af_table (gd32f130.json) exposes ONE advanced timer (TIMER0==TIM1) + general timers (TIMER1/2/13/15/16). No TIM8/TIMER7 equivalent. The F1 ADC path (setup.c:600 ADC_EXTERNALTRIGCONV_T8_TRGO, setup.c:540-545 TIM8 slave-gated to TIM1) cannot port unchanged.

Layering (new fork bipropellant_can_generic, git fork of bipropellant_can, full history + GPL-3):
1. board_table.h/.c (GENERATED by codegen) — static const board_profile_t g_board_table[N] mirroring the pydantic Profile schema EXACTLY (led_red/green/orange/blue colors, AdcChannel.shunt_resistor_milliohms + nested on_pin, PhaseOutputs.timer as a mapped string->enum, GpioPin sentinel). Compiled for ONE family at a time (BOARD_FAMILY define). Each entry carries chip.family + part_hint + a fingerprint; uid field RETAINED in the struct but is empty for all current rows and is NOT used as a runtime selector (see runtime_override).
2. board_select.c (NEW) — boot resolver, PRIMARY path = NVRAM stored_index / serial-forced; best-effort family+part_hint narrowing only; UID match tier is no-op until UIDs exist. Resolves to a single mutable RAM active_profile_t ACTIVE. Runs AFTER a board-independent self-hold latch (see nvram/boot-race fix).
3. board_active.h (NEW) — extern active_profile_t ACTIVE + accessor macros replacing direct defines.h macro use. ALL pin consumers (HAL init AND direct ->IDR/->BSRR/->BRR/->ODR register sites) source from ACTIVE.
4. setup.c (REFACTOR) — MX_GPIO/TIM/ADC/UART init read pin/port/channel/timer from ACTIVE. PWM/ADC peripheral SHAPE is now family-conditional via a new hal_motor abstraction (not just pin sourcing) because single-advanced-timer families need a different ADC trigger + sync topology.
5. hal_motor.h / hal_port.h (NEW) — family abstraction for (a) GPIO pin classes and (b) the motor timer-sync + ADC-trigger topology. Dual-timer (STM32F1) vs single-advanced-timer (GD32/MM32) are distinct implementations behind this seam.
6. Host side: stm32_auto_detect codegen emits board_table.c from data/variants/*.toml (realizing deferred Strategy-B), vendored into bipropellant_can_generic/codegen/.

The firmware NEVER promises live remap of silicon-fixed pins, NEVER applies an override that collides with another active pin or EXTI line, and a fresh unconfigured unit boots to a MOTOR-DISABLED safe default profile.

  ChipFamily enum value  ->  BOARD_FAMILY C define   ->  af_table filename
  STM32F1                 ->  BOARD_FAMILY_STM32F1    ->  stm32f103.json (+ at32f403.json for AT32F4 build)
  GD32F1 (=Gen2 GD32F130) ->  BOARD_FAMILY_GD32F1     ->  gd32f130.json

Codegen filters g_board_table rows by ChipFamily==BOARD_FAMILY and ASSERTS every bundled variant lands in exactly one bin (fails the build if any variant's family is unmapped). The 3 GD32E2/gd32e230 rows are now explicitly their own bin (previously dropped). AT32F4 reuses the STM32F1 bin/HAL with only an ldscript flash-size delta.

g_af_validity[] (GENERATED from the family's af_table json) gives pin->legal {peripheral,channel,af} for the SILICON-FIXED check. It is necessary but NOT sufficient: two ADDITIONAL validators run at override/resolve time (see runtime_override): a profile-wide PIN-UNIQUENESS check and an EXTI-LINE-ALLOCATION check, neither of which g_af_validity captures.

Per-family row counts in each binary: STM32F1 build -> 3 rows (efru v0 dual-motor, efru v1 dual-motor, robodurden-stm32f103 single-motor); GD32F1 build -> 18 rows (17 robodurden gd32f130 + flo199213 master, all single-motor); GD32E2 build -> 3 rows (gd32e230 single-motor); MM32SPIN0X build -> 1 row (single-motor, experimental).

## Runtime override + live/reboot matrix
RUNTIME OVERRIDE + PIN-CLASS LIVE/REBOOT MATRIX + THREE-VALIDATOR GUARD:

Selection model (corrected — auto-detect demoted):
 - PRIMARY = NVRAM stored_index OR serial/CAN-forced index. Documented as THE selector.
 - BEST-EFFORT = family + part_hint narrowing only (no live fingerprint: firmware cannot read a board's physical pinout from silicon, so same-family layouts e.g. the 17 GD32F1 rows are runtime-INDISTINGUISHABLE). If narrowing leaves >1 candidate, REQUIRE stored_index/serial; never guess.
 - UID tier = NO-OP (0/24 rows have a uid). Struct field retained for future capture.
 - g_default_board_index points at a MOTOR-DISABLED safe profile so a fresh/unconfigured unit cannot energize wrong phase pins. Motors enable only once a profile is explicitly selected and committed.

board_apply_override(field_id, gpio_pin_t newpin) runs THREE validators in order, returning REJECTED on any failure:
 (1) SILICON legality via g_af_validity (timer-channel/ADC-channel/AF must be legal for that pin on this family).
 (2) PROFILE-WIDE PIN-UNIQUENESS: reject if newpin is already claimed by any other active function in the resolved profile (halls, button PA1, charger PA12, MCP2515 INT PB12, CAN soft-SPI PA2/PA3/PB10/PB11, LED/buzzer, phases, ADC pins). This is NEW — g_af_validity does not catch double-assignment.
 (3) EXTI-LINE ALLOCATION (for hall/EXTI-class only): EXTI line == pin NUMBER; ISR mux is fixed (EXTI9_5 -> pins 5-9, EXTI15_10 -> pins 10-15). Reject if newpin's pin-number collides with any other EXTI-active pin in the profile (other halls, button, charger, MCP2515 INT). Returns REJECTED (NOT PENDING_REBOOT) on collision.

Routing by pin class (only after all applicable validators pass):
LIVE (HAL_GPIO_Init new, deinit old, immediately):
 - LED colors (led_green=PB2 on F1 reference), BUZZER, BUTTON, CHARGER_DETECT — all GPIO-class.
 - CAN software-SPI MOSI/MISO/SCK/CS/INT — via new SoftSPI_Rebind(); these use direct ->BSRR/->BRR/->IDR so rebind MUST update ACTIVE-sourced port/pin used by software_spi.c (not macros).
 - IMPORTANT consumer fix: charger live read at main.c:869 and ascii_proto_funcs.c:255-256 use CHARGER_PORT->IDR (compile-time macro). These direct-register sites are converted to ACTIVE.charger.port->IDR & ACTIVE.charger.pin_mask so a live override actually changes the charging logic. Same for any ->IDR/->BSRR/->BRR/->ODR site (22 sites total incl. bldc.c halls, hallinterrupts.c, software_spi.c, sensorcoms.c).

REBOOT-ONLY (validated + NVRAM-persisted, applied at next peripheral re-init; NEVER live):
 - PHASE PWM complementary CH/CHN pins — rebind=silicon_fixed; override allowed ONLY to another silicon-legal pin for that exact timer channel; else REJECTED_SILICON.
 - ADC phase-current/battery/dc-bus channels — rebind=silicon_fixed; ADCunit+channel pairing must stay legal; reboot-only.
 - HALL EXTI pins — reboot-only AND subject to validator (3); collisions REJECTED.
 - DEAD_TIME / PWM_FREQ / timer-sync config — reboot-only. dead_time_ns is validated per-family: schema default is 1000ns but F1 silicon reference is ~500ns (32 ticks) and GD32 rows use 833ns (60 ticks); codegen carries the per-row value and a per-family legal-range check rejects out-of-range.
 - OFF_PIN self-hold — GPIO-class but FORCED reboot-only (changing the power latch live can drop power mid-run); requires explicit confirm flag; applied only at next boot before latch-high; documented as non-auto-detectable.

API: serial/ASCII + CAN: board_override_set(field,pin) -> {APPLIED_LIVE | PENDING_REBOOT | REJECTED_SILICON | REJECTED_CONFLICT | REJECTED_EXTI}; board_override_clear; board_override_commit (NVRAM); board_select(index|serial). The REJECTED_* paths are the explicit guard against ever lying about live remap or creating a live pin conflict.

## Chip families
PER-FAMILY HAL / LDSCRIPT / STARTUP + MOTOR-TOPOLOGY STRATEGY (the key fix: motor support is a peripheral redesign on single-advanced-timer families, not an init skip):

STM32F1 (STM32F103 / GD32F103 / AT32F403 = ChipFamily STM32F1) — PRIMARY, lowest risk, the ONLY dual-motor family:
 - Reuse existing Drivers/ (STM32F1 HAL), STM32F103RCTx_FLASH.ld, startup_stm32f103xe.s, system_stm32f1xx.c.
 - Motor topology UNCHANGED: TIM1 master, TIM8 slave-gated (setup.c:540-545), ADC1 ext-trig = T8_TRGO (setup.c:600), dual ADC1/ADC2. This is the verified baseline and is preserved behind hal_motor's "dual_adv_timer" implementation.
 - AT32F403 = F1 path; only ldscript flash-size tweak + bench-verify 72MHz clock.

GD32F1 (= the 17 Gen2 GD32F130 boards + flo199213) — SECONDARY, ALL SINGLE-MOTOR:
 - VERIFIED: gd32f130.json exposes ONLY TIMER0 (==TIM1) as the advanced timer; no TIM8/TIMER7. So the F1 dual-timer/TIM8_TRGO path CANNOT port.
 - hal_motor "single_adv_timer" implementation: drive the one motor on TIMER0; re-source the ADC trigger from TIMER0_TRGO (not T8_TRGO); REMOVE master/slave gating. Investigate GD32F130 dual/simultaneous-ADC support BEFORE claiming motor support; if absent, use a single-ADC sequential sampling path for that motor's currents. This is a peripheral redesign, gated and bench-validated for phase/ADC alignment on real Gen2 silicon before M5 claims it drives.
 - Needs GD32F1x0 Firmware Library OR thin compat shim; Cortex-M3 so startup/ld close: add startup_gd32f130.s, gd32f130_flash.ld (64KB), system_gd32f1x0.c. Clock tree differs (HSI 8MHz PLL) -> per-family SystemClock behind BOARD_FAMILY_GD32F1.

GD32E2 (= the 3 gd32e230 boards) — NEW EXPLICIT BIN (was unbinned/dropped), ALL SINGLE-MOTOR:
 - GD32E230 = Cortex-M23. Needs its own startup_gd32e230.s, gd32e230_flash.ld, system_gd32e23x.c, and the gd32e230.json af_table. Single-advanced-timer same as GD32F1 -> reuse hal_motor "single_adv_timer" with the E2 ADC-trigger source verified separately. Treat as EXPERIMENTAL until bench-validated.

MM32SPIN0X (= MM32SPIN05, ChipFamily MM32SPIN0X) — HIGHEST RISK / EXPERIMENTAL, single board, single-motor:
 - Token normalized to MM32SPIN0X (not 'MM32SPIN05'); af_table mm32spin0x.json.
 - Not ST/GD register-compatible for advanced-timer + ADC-trigger paths. Needs MM32 SPIN0x lib, startup_mm32spin0x.s, mm32spin0x_flash.ld, system_mm32.c.
 - Ship motor-DISABLED first (LED/buzzer/button/CAN live-pin path); enable PWM only after bench validation on current-limited supply. Gated behind BOARD_FAMILY_MM32SPIN0X.

GPL-3 (LOAD-BEARING, resolved before M5/M6 not deferred): determine GD32/GD32E2/MM32 vendor peripheral-library redistribution compatibility with GPL-3 BEFORE building those families. If a vendor lib is GPL-incompatible, vendor only CMSIS device headers and fetch the lib at build time, documenting the GPL boundary; the single-repo fork then ships headers + build-time fetch, not the incompatible lib.

Mechanism: hal_port.h (GPIO pin classes) + hal_motor.h (timer-sync + ADC-trigger topology) abstractions; setup.c calls hal_* wrappers so board-table consumers are family-agnostic while the motor peripheral SHAPE is selected per family. platformio.ini env per family (env:stm32f1 / env:gd32f1 / env:gd32e2 / env:mm32spin0x) each defining BOARD_FAMILY and pulling matching HAL/ld/startup + family-filtered board_table.c.

## NVRAM
NVRAM STORAGE — reuse bipropellant flashaccess/flashcontent (mechanism re-described accurately):

VERIFIED mechanism (flashaccess.c:15-16, flashcontent.h): there is NO separate CAN-config sector. CAN_BoardID is a FIELD inside the single FLASH_CONTENT struct, stored in an append-LOG region at 0x08000000 + 0x40000 - 0x800, flashlen=4096 (two 2KB pages). Writes append a new record with a trailing length word; readFlash requires len==sizeof(FLASH_CONTENT) AND magic==CURRENT_MAGIC; a full region triggers page-erase. The old plan's risk text ("clobbering CAN-config sector") MISDESCRIBES this and is corrected below.

Extend FLASH_CONTENT (flashcontent.h, currently ends at PROTOCOL_ADC_SETTINGS adc) APPEND-ONLY so existing field offsets (PID, CAN_BoardID, CAN_BaseID_*, adc) are unchanged:
```
  // --- board-generic additions (appended; bump CURRENT_MAGIC) ---
  unsigned short board_override_valid;   // 0/1
  unsigned short board_selected_index;   // chosen g_board_table index (PRIMARY selector)
  unsigned short board_select_mode;      // 0=default-safe, 1=stored-index, 2=serial-forced
  board_override_t board_override;       // packed gpio_pin_t per overridable field + per-field valid bitmap
```
board_override_t is #pragma pack(2) (matching the existing struct pack).

SIZING (the old plan left this unsized — now explicit and tested): compute sizeof(FLASH_CONTENT) AFTER adding board_override_t. records_per_erase = floor(4096 / ((sizeof+1 rounded to even)+2 length word)). Assert sizeof stays well under 4096 and that records_per_erase remains reasonable (document the flash-WEAR impact, since a larger record means fewer appends between page-erases). A host test asserts the total < 4096 and pre-existing field offsets are byte-identical.

MAGIC: bump CURRENT_MAGIC (config.h:253, currently 1238) so old flash images fail the magic check -> load FlashDefaults -> new fields zero-init -> board_override_valid=0 -> fall back to default-safe (motor-disabled) profile. CAN_BoardID etc. correctly reset to defaults on mismatch (this is the actual safety guarantee, replacing the mischaracterized "sector clobber" framing). Same commit path as existing CAN_BoardID runtime config (can_bus.c). Reboot-only overrides are read by board_select.c at boot AFTER the board-independent self-hold latch but BEFORE peripheral init, so they take effect on next boot exactly as the silicon constraint requires.

## Codegen
CODEGEN CHANGE in stm32_auto_detect (realizes deferred Strategy-B; codegen/__init__.py:28 generate_firmware currently raises NotImplementedError):

New module codegen/c_board_table.py, written against the REAL schema (verified profile.py:36-160), NOT the assumed shapes in the old plan:
  emit_c_board_table(profiles, family: ChipFamily) -> str    # board_table.c
  emit_c_board_table_header() -> str                          # board_table.h
  emit_c_af_validity(family) -> str                           # g_af_validity[] from data/af_tables/<file>
Schema-faithful mapping (these were wrong in the original plan and are corrected):
  - IndicatorPins: enumerate led_red/led_green/led_orange/led_blue + buzzer. There is NO single 'led' field. (efru-v1 indicators are led_green/buzzer=PC13.)
  - AdcChannel: read shunt_resistor_milliohms (not 'shunt_mohm') and nested on_pin (GpioPin), plus divider, adc_unit, channel.
  - PhaseOutputs.timer is a STRING; map via a table {"TIM1":1,"TIM8":8,"TIMER0":1} incl. the GD32 "TIMER0"==TIM1 alias; fail codegen on an unknown timer string.
  - GpioPin serializes as "PA10"; reuse a _pin helper like klipper_config.py:24 emitting {port,pin} or the {0xFF,0xFF} sentinel for None.
  - dead_time_ns: carry the per-row value (default 1000, GD32 rows 833) and emit it; firmware does the per-family legal-range validation.
  - motor_count: derive = 2 if phases_left has any pin else 1 (only the 2 efru rows are dual-motor).
Family normalization: a single FAMILY_MAP {ChipFamily -> (BOARD_FAMILY define, af_table filename)} is the source of truth; emit asserts every bundled variant maps, and the 3 GD32E2 rows go to the GD32E2 bin (not dropped).
Fingerprint computed identically to the existing CLI fingerprint command (SHA-256 of pin slots) for host-tool parity; documented as host-only (firmware cannot self-compute it at runtime).
Jinja2 NOT used (matches codebase; klipper_config.py is template-free string building).
generate_firmware(profile, output_dir) implemented to write board_table.c/.h + g_af_validity into output_dir/generated/. Cross-compile to .bin is delegated to the firmware Makefile.
New CLI: `stm32-auto-detect emit-c-board-table --family GD32F1 -o board_table.c` following the klipper-config arg pattern.
Tests parallel tests/test_klipper_config_codegen.py (see test_plan).

## Risks

- **[high]** GD32F1/GD32E2/MM32 single-advanced-timer chips cannot host the F1 dual-timer/TIM8_TRGO motor topology; ADC trigger + sync is a peripheral redesign, and dual-simultaneous ADC may be unavailable.  
  → hal_motor 'single_adv_timer' implementation: TIMER0-only PWM, ADC trigger re-sourced to TIMER0_TRGO, master/slave gating removed; verify dual-simult ADC per part and fall back to single-ADC sequential sampling if absent. Bench-validate PWM/ADC phase alignment on real Gen2 silicon BEFORE M5/M6 claim drive. All Gen2 boards are single-motor so only one motor path is needed.
- **[high]** Runtime UID auto-detect has zero backing data (0/24 variants have a uid) and firmware cannot self-compute a fingerprint, so the 'auto-detecting universal firmware' premise overstates capability; same-family layouts (17 GD32F1) are indistinguishable.  
  → Demote auto-detect to best-effort family/part_hint; make stored-index/serial the documented PRIMARY selector; UID tier is a no-op. DEFAULT_BOARD_INDEX = motor-disabled safe profile so an unconfigured unit cannot energize phase pins.
- **[high]** Family-token mismatch: ChipFamily values (STM32F1/GD32F1/GD32E2/MM32SPIN0X) differ from old BOARD_FAMILY tokens and from af_table filenames; the 3 GD32E2 variants were unbinned and silently dropped.  
  → Single canonical FAMILY_MAP (enum -> BOARD_FAMILY define -> af_table filename); codegen asserts every variant bins exactly once; GD32E2 gets an explicit bin + HAL/startup/ld.
- **[high]** Free-form override can assign two functions to one pin (e.g. proposed LED->PB12 collides with MCP2515 INT; CAN soft-SPI already reuses USART2/USART3 pins); AF-only validation (g_af_validity) misses this, producing a live conflict.  
  → Add profile-wide pin-uniqueness validator to board_apply_override/board_select; reject any override landing on an already-claimed pin (REJECTED_CONFLICT, never APPLIED_LIVE). Test example corrected to a genuinely free pin.
- **[med]** Hall EXTI override 'within free groups' can collide on the shared EXTI line/ISR (EXTI line==pin number; EXTI9_5/EXTI15_10 mux) and silently break interrupts even after reboot.  
  → Add an EXTI-line-allocation validator distinct from g_af_validity; reject (REJECTED_EXTI, not PENDING_REBOOT) any hall pin whose number collides with another EXTI-active pin (halls/button/charger/MCP2515 INT).
- **[med]** Generated C struct diverged from the pydantic schema (no single 'led'; shunt_resistor_milliohms; timer is a string incl GD32 'TIMER0'; dead_time_ns default 1000 vs F1 ~500ns).  
  → Codegen written against the real schema with led-color enumeration, string->enum timer map, nested on_pin, and per-family dead-time range validation; host round-trip tests on efru-v1 + a GD32 row.
- **[med]** Live override updates ACTIVE but direct ->IDR/->BSRR/->BRR/->ODR sites (charger main.c:869, halls bldc.c/hallinterrupts.c, software_spi.c, sensorcoms.c — 22 sites) keep reading compile-time macros, so the override has no effect.  
  → Convert every direct-register pin site to ACTIVE-sourced port/mask; on-target test that a charger-pin override actually changes the charging read.
- **[med]** Enlarging FLASH_CONTENT reduces records-per-erase in the 4096-byte append-log (more flash wear); old plan left this unsized and mislabeled the mechanism as a separate CAN sector.  
  → Compute sizeof(FLASH_CONTENT) post-change, assert <4096 and reasonable records-per-erase, document wear; correct risk text (no separate sector; guarantee is magic-bump -> FlashDefaults). Host test pins pre-existing field offsets.
- **[med]** Moving NVRAM+table-resolve before the self-hold latch (main.c:320 today asserts latch before init_flash_content:347) inserts flash-read latency into the pre-latch path and may overrun the power-button hold window.  
  → Drive OFF_PIN HIGH as the FIRST GPIO action using a board-independent self-hold default; only self_hold identity must be known pre-latch (compile-time safe default, override is reboot-only/non-auto-detectable). Measure reset->latch time on the reference board vs the hold window before/after.
- **[med]** GD32/GD32E2/MM32 vendor peripheral libraries may be GPL-3-incompatible, blocking the single-repo GPL-3 release (M7).  
  → Resolve license compatibility BEFORE M5/M6; if incompatible, vendor only CMSIS device headers + fetch the lib at build time and document the GPL boundary (release-blocker, not a footnote).
- **[high]** Falsely promising live remap of silicon-fixed PWM/ADC/hall pins could energize wrong phase pins -> destroyed FETs.  
  → board_apply_override returns REJECTED_SILICON for phase/ADC changes and PENDING_REBOOT for legal hall/dead-time; never HAL_GPIO_Init these classes live; default profile is motor-disabled.
- **[low]** AT32F403 flash/clock deltas vs STM32F103RC ldscript.  
  → Treat as STM32F1 bin; adjust ldscript flash length only; bench-verify 72MHz.
